# km-organizer Skill Design

## Overview

A single Claude Code skill that handles both intake (saving new content) and reorganization (restructuring existing content) for the km repository. The primary goal is **maximizing future LLM retrieval quality** — when the user asks an LLM about something later, it should find and answer correctly.

The skill auto-detects which mode (intake vs reorganize) based on user context.

## Design Principles

- **Retrieval over aesthetics** — structure decisions optimize for LLM comprehension, not human browsing
- **Preserve original language** — content stays in whatever language it was written in
- **Keep value, strip fluff** — remove unnecessary decoration, preserve substance
- **Skill decides polish level** — light cleanup or full rewrite, whatever best serves clarity and retrievability per content type
- **Git-friendly** — changes are staged but not committed, user reviews the diff

## Intake Mode

Triggered when the user provides new content (pasted text or file path).

### Step 1: Analyze Input
- Detect content type: note, config, knowledge article, code snippet, guide, project doc, etc.
- Detect language — preserve as-is
- Identify key topics and relationships to existing content

### Step 2: Scan Repo Structure
- Read existing directories, README.md, and MANIFEST.md
- Find the best matching location for the content
- If no good match exists, create a new directory with README.md

### Step 3: Polish Content
- Strip unnecessary fluff, keep valuable substance
- Add YAML frontmatter for retrieval:
  ```yaml
  ---
  title: Docker networking basics
  tags: [docker, networking, devops]
  created: 2026-04-05
  summary: One-line description for LLM context
  related: [coding/tools/docker.md]
  ---
  ```
- Decide per-content whether to lightly clean up or rewrite — whatever maximizes clarity
- Use consistent markdown structure

### Step 4: Save and Update Navigation
- Write the file to the chosen location
- Update the directory's README.md with a link/description
- Update MANIFEST.md at repo root

## Reorganize Mode

Triggered when the user asks to review or restructure part or all of the repo.

### Step 1: Audit
- Scan target scope (full repo or specific directory)
- Read all files, their frontmatter, and content
- Identify: duplicates, orphaned files, misplaced content, overgrown directories, files that should be merged or split

### Step 2: Propose Changes
- Present a summary of findings and a restructure plan
- Show what moves where, what gets merged, what new directories are needed
- Always ask for user confirmation before executing — no silent moves

### Step 3: Execute
- Move/merge/split files as approved
- Update all affected README.md and MANIFEST files
- Update frontmatter `related` links if paths changed
- Stage changes in git without committing

## MANIFEST.md

A repo-root file that acts as a global content map for LLMs.

### Structure
```markdown
# KM Repository Manifest

## Content Map
- coding/ — Development tools, editor configs, CLI preferences
  - coding/claude-code/ — Claude Code settings
  - coding/tools/ — CLI tool documentation
- os-config/ — Shell and OS configuration
...

## Recent Additions
- 2026-04-05: coding/tools/docker-networking.md — Docker networking basics

## Tags Index
- docker: coding/tools/docker-networking.md
- nushell: os-config/nushell/...
```

### Why
Gives an LLM a fast overview of what exists and where, without scanning every file. The tags index enables topic-based lookup.

### Maintenance
Auto-generated by the skill on every add, move, or reorganize. The user never edits it manually.

## Triggering

The skill triggers when the user wants to:
- Save information to the km repo
- Categorize or file content
- Reorganize existing files or directories
- Phrases like "save this", "file this note", "organize this", "restructure coding/"
- Pastes content that looks like notes, configs, or knowledge
